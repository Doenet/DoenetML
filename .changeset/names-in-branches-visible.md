A name inside a `<conditionalContent>` or a one-pick `<select>` is visible outside it, as a `<group>`'s is, and resolves only if every branch declares it with the same type.

- **A plain `$x` from outside finds the `x` in the active case** of a `<conditionalContent>`, as `$cc.x` does, and in the picked option of a `<select>` whose `numToSelect` is written as `1` or left out (`01` picks one, but keeps its names private). It used to name nothing, with a warning. Two cases declaring `x` don't make it ambiguous; an `x` beside the `<conditionalContent>` does. With no `<else>`, an `x` in every case is enough, and `$x` names nothing while no case is active.
- **A `<select>` that picks several keeps its names private**: a name in one pick is reached with an index (`$s[2].x`), under the same every-option, same-type rule, as is `$s[1].x` on a `<select>` that picks one.
- **A name some branch lacks, or that two branches declare with different types, names nothing**, with a new warning at the reference that says which branch lacks it (`doenet-w0183`) or which types differ (`doenet-w0184`). `$cc.x` used to show the active case's `x`, whatever its type, or, while the active case had no `x`, what that case held. A name after it is held to the same rule: `$h.x`, of a `<group name="h">` in every case, needs every branch's `h` to declare `x`, with one type. So does a name after an index into a `<select>` in every case (`$h[1].x`), in each `h`'s options. A `<select copy="$s">` with options of its own is held to the rule with those options too. A property after such a name (`$x.value`) is held to it too: the branches' `x` must have one type, whether or not a component elsewhere is named `value`, bare or on a tag. A name after a tag made from a container (`$m.value` of `<math name="m" extend="$s"/>`) is the tag's own, not a name in the container's branches.
- **On a tag** (`<math extend="$cc.x"/>`), a missing name is an error, as is a name that can be absent because there is no `<else>`; different types stay the error they were (`doenet-e0066`) on a tag that makes one component or a list; a `<group extend="$x"/>` (or `copy`), which would hold a different type with each case, is the `doenet-w0184` message as an error, where it showed whatever the active case held; and a property after names of different types (`<text extend="$x.value"/>`) is the `doenet-w0184` message as an error. A type that already is the tag counts as it, as before: an `<integer>` `x` in one case and a `<number>` `x` in another is fine for `<number extend="$x"/>`, and now for `<number extend="$x.value"/>` too, as the value of either is a number. Such a tag now also follows the case: it showed `NaN` once a case's `<integer>` replaced another's `<number>`. `<math extend="$s[2].x"/>`, past what a one-pick `<select>` picks, is now the error `doenet-w0181`, where it made a blank math, whatever its options declare; so is `<math extend="$h[2].x"/>` of a one-pick `<select name="h">` in every case, and an index past what each of several selectors picks though they pick different numbers.
- **A property the referent doesn't have** (`$n.nonexistent`, `$s[1].nonexistent` of what a `<select>` picks, `$x.nonexistent` of a name in the branches, `$$f.x(2)`) is now a warning (`doenet-w0104`), where it was silent. A property it has, with no value now (`$P.z` of a point in two dimensions), stays silent.

Closes #2450.
