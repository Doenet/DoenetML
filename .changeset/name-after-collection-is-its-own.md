**Behavior change: a name or a property after a collection is the collection's own, never each item's.** A collection is a list (`<mathList>`, `<pointList>`, …), a `<sequence>`, a `<collect>`, a `<sort>`, a `<shuffle>`, a `<sortIndices>`, a `<repeat>`, a `<repeatForSequence>`, a list operator (`<cumulativeSum>`, …), a `<functionIterates>`, and a `<select>` or other random chooser or sampler whose `numToSelect` (or `numSamples`) is written as anything but `1`. After one, a name or a property is its own: `numItems`, the settings every component has (`hide`, `fixed`, `disabled`, …), and the properties the tag declares, such as a list's `maxNumber`. A list's `text`, `latex` and `value` were its entries' read together, not properties of its own, so they name nothing too: write `$ml` for the list, `<text>$ml</text>` for its text, and `$ml[2].text` for an entry's. Anything else now names nothing, with a warning when the document loads that suggests an index: `$pl.x` of a `<pointList>` (was each point's x) → `$pl[1].x`, `$r.P` of a `<repeat>` (was every iteration's `P`) → `$r[1].P`, `$r.P.x` → `$r[1].P.x`, `$s.P.x` of a `<select numToSelect="2">` → `$s[1].P.x`, `$c.P` of a `<collect>` → `$c[1].P` (also `$c.A` for a name it holds once, such as a collected `A`), and a repeat's `$r.v` → `$r[1].v`. A name or property written in another case than an item has it is suggested in the item's case: `$r.X` of a repeat of points → `$r[1].x`, `$pl.X1` → `$pl[1].xs[1]`. A tag made from one (`<point extend="$pl.x"/>`) is missing, with the same warning, where it was an error. This reverts the per-item names and properties of the release that added `numItems`: with them, `$r.fixed` was the repeat's own but `$r.x` each item's, so an author couldn't tell from `$r.something` which it meant.

Which a tag is comes from the tag as written, never from how many items it holds: a `<mathList>` of one entry is still a list (`$ml.x` names nothing), and `numToSelect="$n"` is a collection even while `n` is 1. A name written inside a list, a `<sort>` or a `<shuffle>`, or inside the list an `extend` or `copy` copies, is still that component (`$pl.P` of a `<point name="P">` written in it). A `<group>` holding only a collection, or only a reference to one, stands for it: `$g.x` of `<group name="g">$r</group>` names nothing, as `$r.x` does, and `$g.numItems` is `$r.numItems`.

The same holds for a collection reached through a case or option that declares it, also in a `<conditionalContent>` or one-pick `<select>` inside the case (`$cc.r.P` of a `<repeat name="r">` in a case of `cc` → `$cc.r[1].P`), through an index into an outer repeat or a select that picks several (`$o[1].t.T` → `$o[1].t[1].T`, `$s[1].t.T` → `$s[1].t[1].T`), or that every case or option holds as its one component (`$cc.x` of a case holding a `<pointList>` → `$cc[1][1].x`).

A `<conditionalContent>`, and a `<select>` or other chooser that picks one, are not collections for this: each stands for what it shows, so `$cc.x`, `$s.P` and `$s.P.x` work as before, when every case or option declares the name with one type.

An action's `target` follows the same rule: `<updateValue target="$r.mi"/>` and `<animateFromSequence target="$r.x"/>` name nothing, with the warning, where they changed every iteration's; write `target="$r[1].mi"`. So does `target="$pl.x"` of a `<pointList>`, where it set every entry's x.
