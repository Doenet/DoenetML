More reference cycles are reported when the document loads, as a "circular dependency" error at each reference on the cycle, in every case and variant, while the rest of the document renders. Before, each stopped the document, or gave an error only once a reader reached it. Among them: an attribute a math, boolean, list or `<evaluate>` is made from that refers to the component (`<math name="m" simplify="$m=1">`, `$$f($n)` in `n`); an index written as a number into a `<repeat>`, `<select>`, `<conditionalContent>`, `<shuffle>` or `<sort>` in its own content (`$r[1]` in the template of `r`); a point copied as content in its own label (`<label><p>$P</p></label>`); a text or boolean list holding an index into itself as an entry; an answer's current response read in its own award; an input prefilled from the entry of a list that is the input; a case's condition reading a name its `<conditionalContent>` declares; and a `<collect>` of values whose source holds it or an index into it.

Diagnostic levels follow where a problem comes from more closely. A warning about what the author wrote in a `<conditionalContent>` case, a `<select>` option or a repeat's template (a circle through a point that isn't numerical, a chart value that isn't a number) is now a warning, not an info, and it stays once reported when the case is no longer shown or the iterations are gone. A value a primitive attribute can't take (`<slider type="banana"/>`) is a warning. A style or display attribute of a chart's value (`displayDigits`, `styleNumber`) no longer makes its warning an info. An index past the iterations of a repeat, or after a group of several components, that a value decides (an index from an input, or what the case shown holds) is an info that follows the value, and a reload reports the same. A `<collect>` from a case that is no longer active collects nothing and says so again, each time, as after a reload. A `<selectRandomNumbers>` whose selection is restored on reload reports its diagnostics again.

A property after a `<select>` or `<conditionalContent>` that some of its options or cases have and others lack (`$cc.x` with a math in one case and a text in the other) gives a warning when the document loads, decided from every option and case, and each one that lacks it gives a blank instead of being skipped (`$s.x` of picks holding a math and a text is `x, ＿`). Each item lacking it, or holding several components, gives its own blank wherever the reference is: in a `<p>` or a `<text>` (`x, ＿`), a `<math>` (`<math>$s.x+1</math>` is `(x, ＿) + 1`), a `<mathList>`, an attribute (`x="$s.x"`) or `bindValueTo`, and a `<number>` made from it is missing. The blanks follow a repeat's count as it changes, and a property after a repeat with no iterations, or a `<conditionalContent>` with no case shown, shows nothing and reports nothing, as after a reload. A tag made from it (`<math extend="$cc.x"/>`) follows the case shown. When some options or cases hold one component and others several, an index or a property after the container (`$s[1][2]`, `$s.x`) gives a warning at load naming those holding several and suggesting a name (`$s.P.x`, or `$s[1].P.x` when the select picks several). An index past the case a `<conditionalContent>` shows (`$cc[2]`) names nothing, rather than reaching into what the case holds; `$cc[1]` while no case is shown is an info that follows the case. An index past a repeat through a group holding a reference to it says how many iterations it made, as on the repeat itself. An index into a single value through `<option>$g</option>` has the same level as through `<option>$m</option>`. An extend of an iteration holding `$cc.x` follows the case shown. The child an index after a group of several would have selected, which the warning suggests naming, no longer counts a `<setup>`.

**Behavior change: a property after a group of several components names nothing.** A `<group>` holding several components, an iteration of a repeat whose template holds several, a `<select>` pick whose option holds several, and the case a `<conditionalContent>` shows when it holds several, are only containers: a property after one (`$g.x`, `$r[1].x`, `$r.x`, `$s.x`, `$cc.x`) now shows a blank `＿`, with a warning, where it used to read the property from each component and run the results together (`$g.x` of a group of two points was `13`; `$s.x` of options each holding two points was `3, 5, 3, 5`). To fix a document, name the component you mean and reach it by its name: `<point name="P">` and `$g.P.x`, `$r[1].P.x`, `$s.P.x` (`$s[1].P.x` when the select picks several) or `$cc.P.x`. A group holding one component still stands for it (`$g.x` of a group of one point is its x), and a group's own settings are still its own: `$g.hide`, `$g.fixed` and `$g.disabled` of a group of several are the group's (`$g.fixed` used to run each component's together). When every option or case holds several, the warning is given when the document loads; when only some do, the load warning names them, and the blank of the one shown now comes with an info. A reference whose index comes from a repeat whose number of iterations follows an input (`$s[$i]` in `<repeatForSequence to="$mi" indexName="i">`) now reports what it names as an info that goes with the iteration, as a reload does. A reference cycle through a name in a repeat's own template (`$r[1].m` with `m` in a case and the `<else>`) is found whichever branch is written first.
