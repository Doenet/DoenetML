Every random selection that can appear can be made as written, and this is checked when the document loads (D39, SEL-5 to SEL-7). **This is a breaking change for authors:** a document whose selection fails in some variants now has an error in every variant.

- **A selection that some values keep from being made is an error at load, in every variant** (`doenet-e0073`), naming the value: `<selectFromSequence to="$a" numToSelect="3"/>` with `a` chosen from 1 to 10 reports "when `$a` = 1, it has 1 value to select 3 from". Before, the variants where `a` was 1 or 2 selected nothing, with an info, and the others worked. This covers `<select>`, `<selectFromSequence>` and `<selectPrimeNumbers>`: too few values, options or primes, `coprime` values with no coprime combination, every combination excluded, and `numToSelect` not matching the options a variant name has.
- **It is checked over every value the parameters can take, never by trying variants**, so it doesn't depend on how variants are seeded. Values that depend on each other are taken together: `from="$a" to="$a+2" numToSelect="3"` is fine whatever `a` is. A repeat's `indexName` ranges over every iteration that can exist, with no end when the count comes from an input: `to="$i"` is fine, and `to="$i" numToSelect="3"` is an error, as are `from="$i" to="1000000"` (iteration 1000001 has no value) and a `<select numToSelect="$i">` of three options. Two entries of a selection made without replacement (`$a[1]`, `$a[2]`) are different values, an entry a selection may not select (`$a[2]` when `a` may select one value, or `$a[$k]` with `k` past what `a` selects) is nothing, as when the document runs, and an `exclude` of a selection leaves out only values it can have. A `type="math"` sequence with a `length` has that many values whatever they are, also when they come from another math selection's values or from an index with no end, and one whose parameters are numbers in every variant is counted as a number sequence is (`from="$i" to="$i+3"` under an index with no end). With a `step` that may be 0, an `exclude` may leave out every value, also a step the sequence derives from `from`, `to` and `length` (0 when `to` is `from`). How many values a sequence has, and what they are, is found as the sequence derives them: a letters sequence with a `to` and a `length` but no `from` has fewer values than `length` when counting back from `to` would go before `a`, a number sequence with a `to` and a `length` but no `from` counts back from `to` (`to="3" length="5"` has values from -1), and a letters selection that counts back before `a` (`from="b" step="-1" length="3"`) can select `` ` ``, which isn't letters to another letters sequence reading it. A sequence with all four of `from`, `to`, `step` and `length`, which can't be made, is an error at load (it can't be shown to select) when a parameter reads the variant or an iteration, where before the document failed to load; with parameters that read neither, the document still fails to load, as before. A parameter that may be no number (`$b` when `b` may be `x`, an entry that may be nothing), or a letters sequence's `from` or `to` that may be no letters (`$b` when `b` may be the text `%`), is an error also where how many values there are doesn't depend on it, such as the `from` or `step` of a number or letters sequence with a `length` (or with neither a `length` nor a `to`, when it has 10 values), or the `numToSelect` of a selection with replacement, as is a `numToSelect` that may be `1/0`; in a `type="math"` sequence with a `length`, a symbol in `from` or `step` makes values like any other. Where the check can't decide (an `exclude` that may or may not be one of the values, such as a symbol in a `type="math"` sequence), the error says that it can't be shown, rather than naming a value.
- **A parameter must be in a form the check can analyse** (SEL-6), or it is an error at load (`doenet-e0074`) naming what isn't: a literal; a reference to one value another random selection selects (`$a`, `$a[2]`), a repeat's index or value, or a module attribute; a `<number>`, `<integer>` or `<math>` whose content is in these forms and that has no attribute changing its value; and these combined with `+`, `-`, `*`, `/`, `min`, `max`, `abs`, `floor`, `ceil` and `round`. A boolean parameter (`withReplacement`, `coprime`) is a constant, or one reference alone to another selection's value. So `to="$$f($a)"`, `numToSelect="$m"` with `<number name="m">$a^2</number>`, `withReplacement="$x > 0"` with `x` another selection, `<number valueOnNaN="3">$w</number>`, `<math simplify>$a+2</math>` and a `<boolean>` inside a `<number>` are each an error, and so is a reference the check can't read, even when it is the same in every variant, such as `to="$p.x"` of a fixed point. A parameter, or a `<number>`'s whole content, that reads nothing from the variant or an iteration is its value in any form (`3!`, `<number>pi</number>`, `<number>$n^2</number>` with `n` written as `3`); in arithmetic with a reference, so is a part that references nothing (`$a + 2^3`, `x + $i` in a `type="math"` sequence), but not `$a + $n^2`.
- **The check and the selection compute a parameter with one function.** A selection whose parameters read the variant or an iteration, and one another selection reads a value of, holds each parameter compiled: arithmetic over the references it reads, which it computes when the document runs with the function the check proved it with. So the two can't read a parameter differently. What changes when the document runs: where the attribute's components computed a parameter differently from that arithmetic, the selection now has the arithmetic's value. A letters sequence's `to="$a "` is the letter `$a` holds (the space is no part of it, where before the text `c ` wasn't letters and the sequence had no values), and a constant in such a parameter is computed once when the document loads. A `type="math"` sequence's compiled `from`, `to`, `step` and `exclude` are computed as maths, from the math each constant is written as and the math each reference holds, so its values show as before: `from="$a/3" step="1/3"` selects `5/3`, and `from="pi" to="$a+5"` selects `π + 3`; the check reads their numeric values. Whether a selection can be made with the values it has is likewise one test, which the selection makes before it draws and the check makes for each value its parameters can take.
- **The selection in error is replaced by the error**, so it selects nothing and adds no variants. A copy or extend of it, and a selection that reads it, are the same error, reported once.
- **Unchanged:** a selection whose parameters, in these forms, read nothing from the variant or an iteration (literals, or `<number name="n">4</number>`) reports its own error as before. An option's `selectWeight` and a `<selectRandomNumbers>`'s parameters can't keep a selection from being made, so they aren't checked. The rule that a selection excluding over 70% of its combinations fails (`doenet-e0044`, `doenet-e0051`) is unchanged.
