Every random selection that can appear can be made as written, and this is checked when the document loads (D39, SEL-5 to SEL-7). **This is a breaking change for authors:** a document whose selection fails in some variants now has an error in every variant.

- **A selection that some values keep from being made is an error at load, in every variant** (`doenet-e0073`), naming the value: `<selectFromSequence to="$a" numToSelect="3"/>` with `a` chosen from 1 to 10 reports "when `$a` = 1, it has 1 value to select 3 from". Before, the variants where `a` was 1 or 2 selected nothing, with an info, and the others worked. This covers `<select>`, `<selectFromSequence>` and `<selectPrimeNumbers>`: too few values, options or primes, `coprime` values with no coprime combination, every combination excluded, and `numToSelect` not matching the options a variant name has.
- **It is checked over every value the parameters can take, never by trying variants**, so it doesn't depend on how variants are seeded. Values that depend on each other are taken together: `from="$a" to="$a+2" numToSelect="3"` is fine whatever `a` is. A repeat's `indexName` ranges over every iteration that can exist, with no end when the count comes from an input: `to="$i"` is fine, and `to="$i" numToSelect="3"` is an error, as are `from="$i" to="1000000"` (iteration 1000001 has no value) and a `<select numToSelect="$i">` of three options. Two entries of a selection made without replacement (`$a[1]`, `$a[2]`) are different values, an entry a selection may not select (`$a[2]` when `a` may select one value, or `$a[$k]` with `k` past what `a` selects) is nothing, as when the document runs, and an `exclude` of a selection leaves out only values it can have. A `type="math"` sequence with a `length` has that many values whatever they are, also when they come from another math selection's values or from an index with no end, and one whose parameters are numbers in every variant is counted as a number sequence is (`from="$i" to="$i+3"` under an index with no end). With a `step` that may be 0, an `exclude` may leave out every value, also a step the sequence derives from `from`, `to` and `length` (0 when `to` is `from`). How many values a sequence has, and what they are, is found as the sequence derives them: a letters sequence with a `to` and a `length` but no `from` has fewer values than `length` when counting back from `to` would go before `a`, a number sequence with a `to` but no `from` counts back from `to` (`to="3" length="5"` has values from -1, and `to="2.6"` has 1.6 and 2.6, which aren't whole numbers), and a letters selection that counts back before `a` (`from="b" step="-1" length="3"`) can select `` ` ``, which isn't letters to another letters sequence reading it. A sequence with all four of `from`, `to`, `step` and `length`, which can't be made, is an error at load (it can't be shown to select) when a parameter reads the variant or an iteration, where before the document failed to load; with parameters that read neither, the document still fails to load, as before. A parameter that may be no number (`$b` when `b` may be `x`, an entry that may be nothing), or a letters sequence's `from` or `to` that may be no letters (`$b` when `b` may be the text `%`), is an error also where how many values there are doesn't depend on it, such as the `from` or `step` of a number or letters sequence with a `length` (or with neither a `length` nor a `to`, when it has 10 values), or the `numToSelect` of a selection with replacement, as is a `numToSelect` that may be `1/0`; in a `type="math"` sequence with a `length`, a symbol in `from` or `step` makes values like any other. Where the check can't decide (an `exclude` that may or may not be one of the values, such as a symbol in a `type="math"` sequence), the error says that it can't be shown, rather than naming a value.
- **A parameter must be in a form the check can analyse** (SEL-6), or it is an error at load (`doenet-e0074`) naming what isn't: a literal; a reference to one value another random selection selects (`$a`, `$a[2]`), a repeat's index or value, or a module attribute; a `<number>`, `<integer>` or `<math>` whose content is in these forms and that has no attribute changing its value; and these combined with `+`, `-`, `*`, `/`, `min`, `max`, `abs`, `floor`, `ceil` and `round`. A boolean parameter (`withReplacement`, `coprime`) is a constant, or one reference alone to another selection's value. So `to="$$f($a)"`, `numToSelect="$m"` with `<number name="m">$a^2</number>`, `withReplacement="$x > 0"` with `x` another selection, `<number valueOnNaN="3">$w</number>`, `<math simplify>$a+2</math>` and a `<boolean>` inside a `<number>` are each an error, and so is a reference the check can't read, even when it is the same in every variant, such as `to="$p.x"` of a fixed point. A parameter, or a `<number>`'s whole content, that reads nothing from the variant or an iteration is its value in any form (`3!`, `<number>pi</number>`, `<number>$n^2</number>` with `n` written as `3`); in arithmetic with a reference, so is a part that references nothing (`$a + 2^3`, `x + $i` in a `type="math"` sequence), but not `$a + $n^2`.
- **The check and the selection compute a parameter with one function.** A selection whose parameters read the variant or an iteration, and one another selection reads a value of, holds each parameter compiled: arithmetic over the references it reads, which it computes when the document runs with the function the check proved it with. So the two can't read a parameter differently. What changes when the document runs: where the attribute's components computed a parameter differently from that arithmetic, the selection now has the arithmetic's value. A letters sequence's `to="$a "` is the letter `$a` holds (the space is no part of it, where before the text `c ` wasn't letters and the sequence had no values), and a constant in such a parameter is computed once when the document loads. A `type="math"` sequence's compiled `from`, `to`, `step` and `exclude` are computed as maths, from the math each constant is written as and the math each reference holds, so its values show as before: `from="$a/3" step="1/3"` selects `5/3`, and `from="pi" to="$a+5"` selects `π + 3`; the check reads their numeric values. Whether a selection can be made with the values it has is likewise one test, which the selection makes before it draws and the check makes for each value its parameters can take.
- **A sequence's count that floating point leaves just below a whole number is that whole number, and its values never go past `to`** (`<sequence>`, `<selectFromSequence>`, `<repeatForSequence>`, `<animateFromSequence>`, of numbers and maths): `from="1000" to="1000.3" step="0.1"` computes `(to - from) / step + 1` as 3.99999999999954, and had 3 values; it now has 4. A count is rounded up only when it is short of a whole number by no more than the floating-point error of `from` and `to`: 8 units in the last place of the larger of them, over the step (`8 · Number.EPSILON · max(|from|, |to|) / |step|`), and less than half a step. With `from`, `to` and `step` all whole numbers there is no such error, and counts are as before (`from="1" to="1000000000" step="1000000"` has 1000 values); a `to` off the step's grid keeps its count (`from="0" to="0.9999999999"` has 1 value, `from="1000" to="1000.25" step="0.1"` has 3). When a count is rounded up, including by the `1e-14` of the count it was rounded by before, the last value is `to` itself rather than a value a little past it (`from="0" to="0.3" step="0.1"` ends at 0.3, not 0.30000000000000004), and a sequence counted back from a `to` (no `from`) doesn't begin before 1; except that a sequence whose `from` and step are whole numbers keeps whole-number values (`from="1" to="(0.1+0.7)*10"` is 1 to 8, as before). The check finds the values the selection has, so these are the values it checks.
- **A selection that can't be made as written is always an error, never a selection of nothing with an info.** Since #2468, a failure was reported as an info, the selection missing, when a parameter read something that can change; with this change a selection's parameters are either decided by the DoenetML or proven at load over every value, and never change, so its failure is an error, in `<select>`, `<selectFromSequence>`, `<selectPrimeNumbers>` and `<selectRandomNumbers>`. (One reported only after the document loads, which the load-time check should have found, is shown to a reader as a warning with a blank.) Selections that used to select nothing, with at most an info, are now errors at load:
  - a `numToSelect` that isn't a number: `<select numToSelect="x">`, `numToSelect=""`, `numToSelect="$k+"` with `k` a `<number>`, `numToSelect="-1/0"` (`doenet-e0075`, "`numToSelect` isn't a number"), as the check already reported such a `numToSelect` read from the variant (`doenet-e0073`). A `numToSelect` of `0`, or below, asks for nothing, and still selects nothing with no error;
  - a `<selectFromSequence>` counted by its `length` whose `from` or `step` isn't a number (or letters), which selected `null` (`doenet-e0075`);
  - a `<selectRandomNumbers>` that can't select: a `numToSelect`, `from`, `to` or `step` that isn't a number (`doenet-e0075`); a `type="discreteUniform"` range with no value, as `from` past `to`, a `step` that goes away from `to`, or every value excluded (`doenet-e0036`, which selected nothing silently); and a distribution whose parameters can't be drawn from, as a negative `standardDeviation` (`doenet-w0126` to `doenet-w0132`, `doenet-w0165`, `doenet-w0166`, now at error level; they stay warnings, or infos, for `<sampleRandomNumbers>`, and when `numToSelect` is 0). A `type="discreteUniform"` range that was counted without end, freezing the document, in `<selectRandomNumbers>` and `<sampleRandomNumbers>`, has no values: a `step` of `0` with a `to`, and, with no `to`, stepping past an excluded value with a `step` of `0`, a `from` or `step` that isn't a finite number, or a `step` too small to change a large `from` (`from="3" step="0" exclude="3"`, `step="x" exclude="1 x"`, `from="1e17" exclude="1e17"`). With no `to` and a `from` not excluded, a `step` of `0` still gives that value;
  - a failure the check leaves to the selection, excluding over 70% of the combinations (`doenet-e0044`, `doenet-e0051`) with a range from another selection, and a `<selectRandomNumbers>` reading another selection, is now an error in the variants where it happens, where before it was an info.
- **A `<select>` with an option copied by an index that reads a value, beside an option that names the variants it is for, is an error at load** (`doenet-e0073`): `<option copy="$g[$k]"/>` with `k` another selection can be a different option in each variant, so whether each variant name has an option (`selectForVariants`) can't be shown. Before, the variants without one had a missing selection with an info.
- **A selection that reads a selection extending another in error is that error**, reported once, not an error of its own.
- **A reference in a parameter that names nothing is a blank, as the attribute written empty, and the selection's failure is an error again** (it was reported as an info since #2468): `<selectFromSequence from="1" to="$nothing"/>`, where nothing is named `nothing`, reports "Cannot select 1 values from a sequence of length 0." (`doenet-e0036`) as an error, as `to=""` does, besides the warning about the reference; so do `$nothing+1`, `$nothing.x` and a `<number>` holding `$nothing`, in any parameter of `<selectFromSequence>`, `<selectPrimeNumbers>` or `<select>`. A selection that still selects with the blank (`numToSelect="0"`, `exclude="$nothing"`) is unchanged; `numToSelect="$nothing"` isn't a number, an error (`doenet-e0075`). Beside a value from the variant, the blank is checked in each value: `from="$a" to="$nothing"` is an error at load (`doenet-e0073`, "when `$a` = 1, `to` isn't a number"), as `from="$a" to=""` is. In `withReplacement`, `$nothing` is false, as the document reads it (`withReplacement=""` is true).
- **Text that doesn't parse, or loses a reference in parsing, is a blank in each value the reference reads**: `to="$a+"` (which math parsing reads as one symbol, losing `$a`), `$a-`, `($a` and `$a)`, also inside a `<number>` or `<math>` a parameter reads, are checked as `to="$a*"` is, an error at load (`doenet-e0073`, "when `$a` = 1, `to` isn't a number"). Before, `$a+` loaded with no error and failed in every variant with only an info, and `($a` was reported as not analysable (`doenet-e0074`).
- **The selection in error is replaced by the error**, so it selects nothing and adds no variants. A copy or extend of it, and a selection that reads it, are the same error, reported once.
- **Unchanged:** a selection whose parameters, in these forms, read nothing from the variant or an iteration (literals, or `<number name="n">4</number>`) reports its own error as before. An option's `selectWeight` can't keep a selection from being made, so it isn't checked. A `<selectRandomNumbers>`'s parameters aren't checked at load: one that reads another selection and can't be drawn from in some variants is an error in those variants. A `<selectRandomNumbers type="discreteUniform">` another selection reads has the values it draws from, `from + i · step` (`from="0" to="1" step="0.1"` can select 1, so `numToSelect="floor($a*10)"` from 9 values is an error). The rule that a selection excluding over 70% of its combinations fails (`doenet-e0044`, `doenet-e0051`) is unchanged, and isn't checked at load.
