Every random selection that can appear can be made as written, and this is checked when the document loads (D39, SEL-5 to SEL-7). **This is a breaking change for authors:** a document whose selection fails in some variants now has an error in every variant.

- **A selection that some values keep from being made is an error at load, in every variant** (`doenet-e0073`), naming the value: `<selectFromSequence to="$a" numToSelect="3"/>` with `a` chosen from 1 to 10 reports "when `$a` = 1, it has 1 value to select 3 from". Before, the variants where `a` was 1 or 2 selected nothing, with an info, and the others worked. This covers `<select>`, `<selectFromSequence>` and `<selectPrimeNumbers>`: too few values, options or primes, `coprime` values with no coprime combination, every combination excluded, and `numToSelect` not matching the options a variant name has.
- **It is checked over every value the parameters can take, never by trying variants**, so it doesn't depend on how variants are seeded. Values that depend on each other are taken together: `from="$a" to="$a+2" numToSelect="3"` is fine whatever `a` is. A repeat's `indexName` ranges over every iteration that can exist, with no end when the count comes from an input: `to="$i"` is fine, and `to="$i" numToSelect="3"` is an error, as are `from="$i" to="1000000"` (iteration 1000001 has no value) and a `<select numToSelect="$i">` of three options. Two entries of a selection made without replacement (`$a[1]`, `$a[2]`) are different values, and an `exclude` of a selection leaves out only values it can have. Where the check can't decide (an `exclude` that may or may not be one of the values, such as a symbol in a `type="math"` sequence), the error says that it can't be shown, rather than naming a value.
- **A parameter must be in a form the check can analyse** (SEL-6), or it is an error at load (`doenet-e0074`) naming what isn't: a literal, or a component written as one; a reference to one value another random selection selects (`$a`, `$a[2]`), a repeat's index or value, a module attribute, or a `<number>`, `<integer>` or `<math>` whose content is in these forms; and these combined with `+`, `-`, `*`, `/`, `min`, `max`, `abs`, `floor`, `ceil` and `round`. So `to="$$f($a)"`, or `numToSelect="$m"` with `<number name="m">$a^2</number>`, is an error, and so is a reference the check can't read, even when it is the same in every variant, such as `to="$p.x"` of a fixed point. Content that reads nothing from the variant or an iteration is its value in any form (`3!`, or `$n^2` with `n` written as `3`).
- **Every value is read as the document reads it**, by the functions each component uses when the document runs: `<number>pi</number>` is 3.14…, `<number>e</number>` is 2.71…, `<integer>2.4</integer>` is 2, a `<boolean>` reading a `<number>` is true when it isn't 0, a letters sequence's `to="$a "` (with a space) isn't letters, a `<text>` read as a number is parsed as math (`1e2` is no number), and a `<boolean>` in `<number>$w + 3</number>` is no part of it (3). A component with an attribute that changes how it computes its value (`valueOnNaN`, `convertBoolean`, a `<math>`'s `simplify` or `format`) is known only where the attribute can't change it, such as a number with `simplify`; otherwise it is a value the check can't know. A boolean parameter (`withReplacement`, `coprime`) is what its `<boolean>` computes, also from another selection's value (`withReplacement="$x > 0"` is checked with each value `x` can take); only one whose references can't be read is checked as both true and false. A value the check can't know, such as an option that isn't one value, decides nothing, and a selection that depends on it is reported as one that can't be shown to always select.
- **The selection in error is replaced by the error**, so it selects nothing and adds no variants. A copy or extend of it, and a selection that reads it, are the same error, reported once.
- **Unchanged:** a selection whose parameters, in these forms, read nothing from the variant or an iteration (literals, or `<number name="n">4</number>`) reports its own error as before. An option's `selectWeight` and a `<selectRandomNumbers>`'s parameters can't keep a selection from being made, so they aren't checked. The rule that a selection excluding over 70% of its combinations fails (`doenet-e0044`, `doenet-e0051`) is unchanged.
