Every collection has a `numItems` property: the number of items an index selects among. That is the entries of a list (`<mathList>`, `<pointList>`, …), a `<sequence>`, the random selectors and samplers, the list operators (`<cumulativeSum>`, …), `<functionIterates>`, the components a `<collect>` collects, what a `<sort>` or `<shuffle>` reorders, the iterations of a `<repeat>` or `<repeatForSequence>`, the picks of a `<select>`, and, for a `<conditionalContent>`, 1 while a case is shown and 0 otherwise. It is the collection's own, so it wins over a property of the same name of its items; an item that is itself a collection is reached by index (`$r[2].numItems`). The lists you write keep `numComponents`, and `numPoints`, `numVectors`, `numIntervals` and `numValues` where they had them.

A `<collect>`, `<sort>` or `<shuffle>` of values gives the same properties whichever way it is built. A count or setting it took from the list it is built on now names nothing, with the usual warning, as it does after a `<collect>` of paragraphs: `$c.numPoints` and `$c.numComponents` of a collect of points, `$s.numValues`, `$s.maxNumber` and `$s.unordered` of a sort. Use `numItems`. Any other property after it is still that property of each item (`$c.x` is each point's x).

A collection's settings are its own: `$s.fixed`, `$r.fixed`, `$cc.disabled` and `$pl.fixed` read the select, repeat, conditional content or list itself, not each item, where they used to give each item's. Reach an item's by index (`$pl[2].fixed`).

**Behavior change: `<functionIterates>` shows its iterates.** It is a collection: it shows its iterates separated by commas, where it showed nothing, an index selects an iterate (`$fi[2]`), a property after it is that property of each iterate, and `numItems` counts the iterates. Add `hide` to a `<functionIterates>` that should not be seen. The properties `iterates`, `finalIterate` and `allIteratesWithInitial` are as before; `numIterates` is still an attribute, but not a property (read the count with `numItems`), and `$fi.numDimensions` is now each iterate's (`2, 2`, was `2`).

**Behavior change: an index after a `<solveEquations>` names nothing.** It is one thing, not a list. `$s[1]` was the first solution; it is now a blank with a warning suggesting `$s.solutions[1]`, which is the first solution.

A `<ray>` whose endpoint, a point it goes through, or its direction is missing (`through="$nothing"`, `endpoint="$pl[3]"` while `pl` has two points) is missing and not drawn, and is made again once the point is there. So is a `<circle>` or `<regularPolygon>` with a missing `center`, a `<rectangle>` with a missing `center`, and a `<parabola>` with a missing `vertex`. A `<regularPolygon>` or `<rectangle>` with a missing center stopped the document before.

**Behavior change: a `<sort>` or `<shuffle>` takes items of one type.** A list among its children still gives its entries as items, so several lists are sorted together, and a `<number>` and a `<math>` are one type for sorting. Items of more than one type, such as a `<number>` and a `<text>`, a `<point>` and a `<vector>`, or a `<math>` and a `<group>` of several components, are now an error when the document loads, shown in place of the items: give each type a `<sort>` or `<shuffle>` of its own. They used to be sorted together as text.

**Behavior change: a `<shuffle>` moves a `<group>` of several components as one item.** A shuffle of three groups of two keeps each pair together, where it used to shuffle all six components; the items of a `<repeat>`, `<select>` or `<conditionalContent>` holding several components are moved whole the same way. Documents that shuffle groups get different variants. A `<sort>` of a group of several is an error, since it has nothing to compare: sort a `<collect>` of its components instead. A group of one component is sorted or shuffled as that component.

A `<sort>` keeps a blank and puts it last: a reference that names nothing (`<sort>$nothing 3 1</sort>` is `1, 3, ＿`, where it dropped it), an index past the end of a list, a blank entry of a list, a tag of something missing, and a number with no value (`NaN`), which used to leave the list unsorted. Text beside the components of a `<sort>` or `<shuffle>` is read as their type where it reads as it (`<sort><number>$x</number> 3 1</sort>` sorts all three), where it was left out with a warning. Beside points or vectors only text with coordinates reads as one, and beside booleans only `true` and `false`, so `<sort><vector>(1,2)</vector> 3</sort>` is an error of two types. Beside components with no value to compare, such as `<p>`s, it is read as text, so `<shuffle><p>a</p> b</shuffle>` is an error of two types, where the text was left out with a warning.

A name after a `<repeat>`, a `<repeatForSequence>` or a `<select>` that picks several reaches that component in every item: `$r.P` is the `P` of every iteration and `$r.P.x` their x's, where they named nothing, and `$s.P.x` is each pick's `P`'s x, where it was ambiguous. Every `<option>` must declare the name, with one type, as for a select that picks one. A name declared in each case of a `<conditionalContent>` in the template is the one in the case each item shows, and follows it when the case shown switches. With an index, `$r[2].P` is still the one of the second iteration. The warnings for a property after a repeat or a select whose items hold several components now suggest `$r.P.x`, and say that each item holds that many components.

A property after a `<repeat>` whose template holds several components is reported when the document loads, also while the repeat has no iterations. An item of a repeat that lacks the property, through its `for` (`for="$A $t $B"` of a point, a text and a point) or a `<conditionalContent>` in its template, gives a blank there with a warning (`$r.x` is `1, ＿, 2`, where the text was dropped silently). An `<option>` holding only a reference counts as what it names. After a `<group>` holding only `$r`, or only a `<group>` or a reference to a group holding only `$r`, a property or a name is the one after `r`, with commas (`$g.x` was `12`), and `$g.numItems` is `$r.numItems`.

**Behavior change: a tag made from a property after a collection of several is an error.** `<point extend="$s.x"/>` of a select of two picks, `<math extend="$r.x"/>` and `<math extend="$pl.x"/>` of a `<pointList>` of two points are the same error as `<point extend="$s"/>`, where they gave `(0, 0)` or a blank silently. Write `<math>$r.x</math>` to read them all as one value, or use one item's (`$r[1].x`).

`$r[1].x` once a repeat has no iterations gives the same information live as after a reload.

**Behavior change: a collection's attributes are not properties.** A property after a collection is that property of each item, so an attribute of the collection no longer shadows the items' properties: `$c.maxNumber` of a `<collect>`, `$s.sortVectorsBy` of a `<sort>`, `$sel.numToSelect` and `$sel.withReplacement` of a `<select>`, `$fi.numIterates` of a `<functionIterates>`, `$ss.side` of a `<searchSorted>`, `$ml.splitSymbols` and `$ml.functionSymbols` of a `<mathList>` and the like are now each item's, a blank with a warning where the items don't have it. Read the count with `numItems`. A collection's own properties are `numItems` and the settings every component has (`hide`, `fixed`, `disabled`, …). Kept, as documented properties: a list's `maxNumber`, `unordered` and `mergeMathLists`, a `<tally>`'s `categories`, and the distribution a sampler draws from (`$x.mean`, `$x.variance`, …).

A repeat's `valueName` and `indexName` after the repeat are each iteration's: `$r.v` is every value (it showed nothing). A name after a `<collect>` is the component of that name in each component collected (`$c.P`, where it was ambiguous), when it holds that name more than once, also when the components collected are themselves each named `P`.
