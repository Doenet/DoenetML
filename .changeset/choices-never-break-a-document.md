A random choice no longer stops a document from loading, a select never chooses again once it has chosen, and whether a choice is an error no longer depends on the variant (D38, DIAG-7).

- **A select never chooses again.** What decides a selection, such as `numToSelect`, `withReplacement` and the range of a `<selectFromSequence>` or `<selectPrimeNumbers>`, is fixed when the selection is made: a later change to it, as from an input in `numToSelect="$mi"`, is ignored. When a reference in one of these attributes decides it, the selection, with the `numToSelect` it was made with, is now saved, so a reload keeps it too. Before, a reload chose again with the new value.
- **A requested variant's choices are taken as given**, even when they are not what the select would choose now, as when a variant was saved before the document changed, such as a `numToSelect` raised from 2 to 4. A `<select>` and a `<selectRandomNumbers>` threw, so the document failed to load. A `<selectFromSequence>` or `<selectPrimeNumbers>` showed an error and selected nothing (`doenet-e0037`–`e0040`, `doenet-e0048`–`e0050`, which are no longer reported).
- **A `<select>` whose options are written with `copy` loads and picks among them**, as among written ones (B39). It failed to load when every option was a copy, and when only some were, the variant never picked a copied one. An `<option copy>` is counted as one option when the document's variants are counted. A bare reference among the options (`$o`), which can stand for any number of them, can't be counted, and says so with the new info `doenet-i0056`.
- **A selection that a value decides can't be made is missing, with an info, not an error.** `<selectFromSequence from="1" to="$a" numToSelect="3"/>`, with `a` from another random choice, gave an error in the variants where `a` was below 3 and none in the others. It now selects nothing in those variants and reports `doenet-e0036` as an info. The same holds for `<select numToSelect="$n">` with too few options (`doenet-e0035`), or with a different number of options for a variant name than it selects (`doenet-e0032`), where the select shows a blank, `＿`; for `<selectPrimeNumbers>` (`doenet-e0047`, `doenet-e0051`), and for the `coprime`, `exclude` and `excludeCombinations` failures of `<selectFromSequence>` (`doenet-e0041`–`e0046`). When every attribute deciding it is written without a reference, and every option of a `<select>` is written in it (an `<option copy>` with no index from a value counts), it is still an error, in every variant. The two "extremely unlikely fluke" failures (`doenet-e0052`, `doenet-e0053`) depend only on the variant, so they are always infos. So does a `coprime` selection whose two hundred random draws find no coprime numbers among values that are not all sharing a factor: it now reports the new info `doenet-i0057`. `doenet-e0045` is kept for values that all share a factor, which no draw can get past. An error for a variant name with no option, or an option for a name the document doesn't have (`doenet-e0033`, `doenet-e0034`), is no longer hidden in the variants where a `numToSelect` from a value also mismatches. When an option comes from a copy with an index from another random choice, these are infos, as the variant decides them.
- **A selection that couldn't be made no longer breaks the document when it is given back**: when the document is reloaded with the variant it saved, or the select is copied with `copy`. A `<selectFromSequence>` or `<selectPrimeNumbers>` whose failure is found after its range is counted (such as `coprime` or `exclude`) threw, so the document failed to load.

Closes #2389 and #2448.
