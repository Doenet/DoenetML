# @doenet/cells-viewer

A viewer for the cells core: React for the document tree, JSXGraph with
Doenet's look for graphs (ADR 0010), the core on the main thread, cells
read straight from wasm memory (ADR 0001). `src/EditorViewer.tsx` puts the
shared `@doenet/codemirror` editor beside the rendered document, in the
shape of the `EditorViewer` in `packages/doenetml-prototype`; `dev/` is the
test page around it, laid out like `packages/doenetml/dev`.

## Running locally

From the repository root, after `npm install`:

```bash
npm run dev -w @doenet/cells-viewer
```

`dev` is a wireit service: it first builds `@doenet/parser` (the DoenetML
parser the viewer runs in the browser), `@doenet/codemirror` (the editor)
and `@doenet/cells-core` (the core compiled to wasm in
`packages/cells-core/pkg`) if their sources changed, then serves the page
at http://localhost:5173. The first build is long: the editor's language
server depends on the main Rust core.

The page opens on `dev/testCode.doenet`, or on what you last typed: the
source is saved to local storage as you edit, and Reset clears it. Edit
the source and press Refresh (Ctrl/Cmd+S) to rebuild. After changing Rust,
restart `dev` (or run `npm run build -w @doenet/cells-core` beside it) and
reload.

## Tests

```bash
npm run build -w @doenet/parser -w @doenet/cells-core
npm run test -w @doenet/cells-viewer
```

`src/prerender/render-to-html.test.tsx` renders documents to HTML in
Node, as a server prerendering a page would: the core's golden documents,
the benchmark's documents and the dev page's, each parsed and loaded as
the browser does and rendered with `renderToString`. JSXGraph cannot load
outside a browser, so the tests replace it with
`src/prerender/jsxgraph-stub.ts` (`vitest.config.ts`): a graph renders as
its board's container, sized and empty. A renderer that reads a store
value goes through `useStoreSnapshot` (`src/hooks.ts`), which gives React
the server snapshot it needs there.

## Prerendering

```bash
npm run build -w @doenet/cells-viewer            # the client build, dist/
npm run build:prerender -w @doenet/cells-viewer  # the server build, dist-prerender/
node scripts/prerender.mjs <document.doenet> --out <page.html> [--seed <n>] [--state <state.json>]
```

A prerendered page is a document rendered to HTML in Node, so it paints
before any script or the core's wasm arrives. `src/prerender/render.tsx`
(`prerender`) parses and loads the document as the browser does, with
the seed and saved state the page names, and renders it with
`renderToString`; `src/prerender/page.ts` (`writePage`) writes the page:
the viewer's styles inlined, the document's HTML in `#root`, the
DoenetML source and the load's seed and state in JSON script elements,
and the client build's files to load the live viewer, as module scripts
that do not hold up the first paint. A graph is its board's container,
sized and empty, until JSXGraph draws it in the browser.

`scripts/prerender.mjs` reads the client build's files from its manifest
(`dist/.vite/manifest.json`) and starts the server's core from the client
build's wasm, so a page and its server run the same core. Until the client
build has the module that replaces a prerendered page with the live
viewer, a page has no scripts and stays as rendered.

The toolbar, besides what the other test viewers have:

- **Evaluator** (`?eval=full|dirty-closure`): how a tick recomputes the
  document.
- **Fixture** (`?doc=<spec>`): a document generated by `npm run fixtures`
  in `../cells-core`, loaded pre-encoded (`?fmt=json|cdast` picks the wire
  format) with its DoenetML shown in the editor. The menu lists the
  fixtures present when the dev server started, and is absent when none
  have been generated.

A strip under the header reports the load time and draws the latest
ticks, as many as the width holds: stacked bars of busy time (the core, the JSXGraph boards' redraw,
React's commit, the browser's paint of the frame) on a square-root scale
against a line at one frame's budget, red-flagged above it. Hover a bar
for its numbers; the tooltips carry the detail.

The browser measurements are in `packages/benchmark` (`npm run browser`
there), which drives this viewer through its `window.__cells` hook
(`dev/main.tsx`) on a `vite build` of it.

`src/renderers/jsxgraph/doenet.ts` and the CSS in `src/viewer.css` are
copied from `packages/doenetml`'s renderers, with the upstream files named
in their headers; those utilities are not exported from that package yet.
