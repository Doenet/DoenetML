# `<summaryStatistics>{:dn}`

<ComponentDisplay name='summaryStatistics'/>

`<summaryStatistics>{:dn}` is a [General Operator](../concepts/essentialConcepts#component-types)
component that renders a table of statistics — mean, standard deviation, median,
quartiles and the rest — for the numbers it is given.

The numbers are its children: bare numbers, [`<number>{:dn}`](number) and
[`<math>{:dn}`](math) components, or — far more often — a reference to numbers that
already exist, such as `$scores` naming a [`<numberList>{:dn}`](numberList) or `$counts`
naming a [`<tally>{:dn}`](tally). Bare numbers are read the way [`<sum>{:dn}`](sum) reads
them, so `<summaryStatistics>1/2 3/2</summaryStatistics>` summarizes a half and three
halves rather than nothing.

Use `statisticsToDisplay` to choose which appear, or leave it out for a standard
selection. `default` and `all` name a set of statistics rather than excluding the ones
beside them, so `statisticsToDisplay="default sum"` shows the standard selection and the
sum. Every statistic is also a readable property, so a sentence can quote the same
number the table shows.

Values that are not numbers count as missing and are left out, which is why `count`
reports how many values were usable rather than how many were given. If nothing usable
is left — an empty list, or a [`<repeat>{:dn}`](repeat) that produced nothing —
`count` is `0` and every other statistic has no value at all: its cell in the table is
left blank, and a reference to it reads as `NaN`.

`displayDigits`, `displayDecimals`, `displaySmallAsZero`, `padZeros` and
`avoidScientificNotation` shape the numbers the table prints, and only those. The
properties always carry the full-precision value, and `count` is never reshaped either
way — it is an exact tally, and rounding it would misreport how many values there were.

## Examples

### Example: statistics of a list


```doenet-editor-horiz
<numberList name="scores">72 91 65 88 79 91 84</numberList>

<p>Scores: $scores</p>

<summaryStatistics name="stats">$scores</summaryStatistics>

<p>The mean is $stats.mean and the median is $stats.median.</p>
```



The table and the sentence read from the same component, so they cannot disagree.



---

### Example: choosing which statistics to show


```doenet-editor-horiz
<numberList name="scores">72 91 65 88 79 91 84</numberList>

<summaryStatistics statisticsToDisplay="count mean stdev" displayDigits="3">
  $scores
</summaryStatistics>

<summaryStatistics statisticsToDisplay="all" displayDigits="3">
  $scores
</summaryStatistics>
```



Both tables list `mean` before `stdev` before `count`: statistics appear in a fixed
order whatever order they are asked for in, so two documents showing the same set read
the same way. `displayDigits="3"` rounds the mean to `81.4` in both, and leaves the
`count` of `7` alone.



---

### Example: summarizing a simulation


```doenet-editor-horiz
<setup>
  <numberList name="pop">30 45 12 60</numberList>
  <cumulativeSum name="cum">$pop</cumulativeSum>
  <number name="total"><sum>$pop</sum></number>
</setup>

<sampleRandomNumbers name="draws" type="discreteUniform"
  from="1" to="$total" numSamples="80" hide />
<searchSorted name="which" target="$draws" hide>$cum</searchSorted>
<tally name="counts" categories="1 2 3 4" hide>$which</tally>

<p>Counts by subpopulation: $counts</p>

<summaryStatistics statisticsToDisplay="count sum minimum maximum mean">
  $counts
</summaryStatistics>

<callAction actionName="resample" target="$draws">
  <label>Draw again</label>
</callAction>
```



The statistics are of the four counts, not of the 80 draws — so `sum` is the sample size
and `mean` is how many draws an average subpopulation received. Drawing again updates
both the counts and the table.
