# `<repeat>{:dn}`

<ComponentDisplay name='repeat'/>

`<repeat>{:dn}` is a [General Operator](../concepts/essentialConcepts#component-types)
component that performs the requested operations in an iterative manner over the component specified (typically,
this is a list or an array). If the specified component is a `<sequence>{:dn}`, a shorter method is to
use the [`<repeatForSequence>{:dn}`](repeatForSequence.mdx) component.

The behavior of the `<repeat>{:dn}` component is similar to a for loop in other programming languages. 


<AttrPropDisplay name='repeat'/>

## Examples

### Example: `<repeat>{:dn}` a series of rectangles within a `<graph>{:dn}`


```doenet-editor-horiz
<numberList name="n">
  1 1 2 3 5 8 13
</numberList>

<graph 
  size="small" 
  xmin="-1" 
  xmax="8" 
  ymin="-2" 
  ymax="14">
    <shortDescription>A graph of rectangles</shortDescription>
    <repeat 
      for="$n" 
      valueName="v" 
      indexName="i">
        <rectangle 
          center="($i, $v/2)" 
          width="1" 
          height="$v" 
          filled/>
  </repeat>
</graph>      
```



A `<repeat>{:dn}` can be used to generate multiple graphical elements at once when placed within a `<graph>{:dn}`.



---

### Example: `<repeat>{:dn}` a user-specified number of inputs


```doenet-editor-horiz
<p>
  <mathInput name="n"><label>How many answers do you have?</label></mathInput></p>

<sequence name="s" from="1" to="$n" hide/>

<p><m>x = </m>
<repeat name="inputs" for="$s">
  <mathInput><shortDescription>one of the answers</shortDescription></mathInput>
</repeat>
</p>

<p>Here are your answers: 
  <c>inputs[1]</c> = $inputs[1], 
  <c>inputs[2]</c> = $inputs[2], 
  <c>inputs[n]</c> = $inputs[$n]</p>
```



A `<repeat>{:dn}` can be used to generate a user-specified number of `<mathInput>{:dn}` components.
For an alternative way to do this, see the [`<repeatForSequence>{:dn}`](repeatForSequence.mdx) component.

### Example: `<repeat>{:dn}` a list of `<text>{:dn}` elements


```doenet-editor-horiz
<setup>
<textList name="plant">
  tree flower cactus
</textList>
</setup>

<p>Say hello to a list of plants:
  <repeat for="$plant" valueName="p">
    <p>Hello, $p!</p>
  </repeat>
</p> 

<p>The second plant is a <c>plant[2]</c> = $plant[2].</p>
```



A `<repeat>{:dn}` can be used with non-mathematical components as well. Individual
entries can be accessed using array notation.




### Example: Use `<repeat>{:dn}` in a combinatoric way


```doenet-editor-horiz
<p>Names: 
  <textList name="names">Donald Kermit Elmo</textList>
</p>
<p>Toys:
  <textList name="toys">whistles yo-yos</textList>
</p> 
<p>Number of toys:
  <numberList name="numToys">7 2 5</numberList>
</p><hr/>

<repeat name="nameR" for="$names" valueName="N">
  <repeat name="toyR" for="$toys" valueName="t">
    <repeat name="numR" for="$numToys" valueName="n">
      <p>$N has $n $t.</p>
    </repeat>
  </repeat>
</repeat><hr/>

<p>The third number of the first toy, belonging to the second name is reference by 
  <c>nameR[2].toyR[1].numR[3]</c>: 
  $nameR[2].toyR[1].numR[3]
</p>
```


Use nested `<repeat>{:dn}` components to iterate across all combinations of the specified components.

### Example: Use `<repeat>{:dn}` in a selective way


```doenet-editor-horiz
<p>Names: 
  <textList name="names">Donald Kermit Elmo</textList>
</p>
<p>Toys:
  <select 
    name="toys" 
    numToSelect="3" 
    withReplacement>
      <option>whistles</option>
      <option>yo-yos</option>
  </select>
</p>
<p>Number of toys:
  <select name="num" numToSelect="3">
    7 2 5
  </select>
</p><hr/>

<repeat 
  name="nameR" 
  for="$names" 
  valueName="N" 
  indexName="i"
  >
    <p>$N has $num[$i] $toys[$i].</p>
</repeat><hr/>

<p>The second name has <c>nameR[2]</c>: 
  $nameR[2]
</p>
```

To achieve parallel iterative behavior, a combination of the `indexName` and `valueName`
attributes can be used.

### Example: Generate a user-specified number of random `<point>{:dn}` components

```doenet-editor-horiz
<p>
  <mathInput name="n"><label>How many points do you want to generate?</label></mathInput></p>
<em>(Note, more than 10 takes some processing time...)</em>

<sequence name="s" from="1" to="$n" hide/>

<graph><shortDescription>A graph of random points</shortDescription>
  <repeat name="randomPoints" for="$s">
    <point>
      (<sampleRandomNumbers 
         from="-10" to="10"/>, 
      <sampleRandomNumbers 
        from="-10" to="10"/>)
    </point>
  </repeat>
</graph>

<p>The generated points are: 
  <c>randomPoints</c> = $randomPoints
</p>

<p>The <m>n^{th}</m> generated point is: 
  <c>randomPoints[$n]</c> = $randomPoints[$n]
</p>
```


A `<repeat>{:dn}` can be used to generate a user-specified number of randomly placed `<point>{:dn}` components.
For an alternative way to do this, see the [`<repeatForSequence>{:dn}`](repeatForSequence.mdx) component.

### Example: Reading a named component of every iteration


```doenet-editor-horiz
<repeat name="r" for="1 2 3" valueName="v">
  <point name="P">($v, $v^2)</point>
  <text name="t">point $v</text>
</repeat>

<p>Every <c>P</c>: $r.P</p>
<p>The x of every <c>P</c>: $r.P.x</p>
<p>The <c>P</c> of the second iteration: $r[2].P</p>
<p>Every value: $r.v</p>
```

A name after a `<repeat>{:dn}` reaches the component of that name in every
iteration, so `$r.P` is all three points and `$r.P.x` their x-coordinates.
With an index first, `$r[2].P` is the one of the second iteration. The
`valueName` and `indexName` are names in every iteration too: `$r.v` is the
value of each.

A property written right after the `<repeat>{:dn}`, such as `$r.x`, reads that
property of what each iteration holds only when what is written inside the
`<repeat>{:dn}` is one component. Here each iteration holds a point and a text,
so `$r.x` names nothing, and you name the one you mean: `$r.P.x`.

### Example: What `for` holds, and one type


```doenet-editor-horiz
<repeat name="data" for="1 2 3" valueName="k">
  <point name="P">($k, $k^2)</point>
  <text name="L">P$k</text>
</repeat>

<p><repeat for="$data" valueName="d">$d.P is labelled $d.L. </repeat></p>

<text name="t">hello</text>
<p><repeat for="2 $t" type="text" valueName="w">[$w]</repeat></p>
```

The items of `for` are read as a `<shuffle>{:dn}` reads its children. Text written in `for` is split at spaces into items, and a list, or
a `<repeat>{:dn}` or `<select>{:dn}` whose iterations or options each hold one
component, gives one item for each of its entries. A `<group>{:dn}` holding
one component stands for that component. Anything holding several components
is one item: a `<group>{:dn}` of several, or an iteration of a
`<repeat>{:dn}` that holds several. So the second repeat above goes once for
each iteration of `data`, and `$d.P` and `$d.L` are the point and the text
named in that iteration.

The items of `for` are all of one type, which you can tell from the DoenetML:
a `<math>{:dn}`, a `<number>{:dn}` or an `<integer>{:dn}` (which count as one
type), a `<text>{:dn}`, a `<boolean>{:dn}`, one kind of graphical object such
as `<point>{:dn}`, or content such as `<p>{:dn}` and anything holding several
components. An input counts as what it holds. Items of more than one type are
an error, reported when the document loads, and the `<repeat>{:dn}` shows the
error in place of its iterations.

Text written in `for` is read as math unless `type` says otherwise, so
`for="2 $t"`, with `t` a `<text>{:dn}`, is an error until it says
`type="text"`, as above. When `type` is written, every item of `for` must be
of that type.

## Property Examples

### Property Example: numItems


```doenet-editor-horiz
<numberList name="values">1 2 3 4</numberList>
<p><repeat name="r" for="$values" valueName="v"><math>$v^2</math></repeat></p>
<p>Number of iterations: $r.numItems</p>
```

`numItems` is the number of iterations, which an index selects among
(`$r[2]` is the second). Any other property after a repeat is that property
of what each iteration holds.
