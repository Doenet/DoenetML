# @doenet/cells-core

A DoenetML core organized around a flat list of `f64` cells: components and
props name cells, and the dependency graph is a list of operators with
inverses. `ARCHITECTURE.md` is the map, `CONTEXT.md` the vocabulary,
`docs/adr/` the decisions.

- `crates/cells-core`: the core, with math-expressions-rs as its symbolic
  engine (`src/sym/`, ADR 0011).
- `crates/cells-wasm`: the browser binding; `npm run build:rust` puts it in `pkg/`.
- `crates/cells-docgen`: synthetic DoenetML for the fixtures.
- `crates/cells-bench`: fixture helpers, `stats`, and the `golden` example
  behind `golden-diff`. Timings live in `packages/benchmark`.
- `scripts/`: the parser wrapper (`parse-dast.mjs`), the binary encoder
  (`cdast-encode.mjs`), fixture generation and the refactoring guards.
- `fixtures/`: generated by `npm run fixtures`; only `sir.doenet` is
  hand-written and committed.

Tags the core understands: `document`, `graph`, `point`, `number`,
`numberInput`, `booleanInput`, `slider` (numeric mode), `math`, `evaluate`,
`repeatForSequence`, `collect`, `line`, `lineSegment`, `circle`, `polygon`
(and `triangle`), `pointList`, `p`, `setup`, `stickyGroup`, `mathInput`,
`function`, `derivative`, `answer` (math, `type="text"` with a `textInput`,
or a `choiceInput` of `choice`s), `conditionalContent` (`case`, `else`) and
`feedback`, `select` (`option`), `selectFromSequence` (literal bounds, one
pick), `hint`, `group` (and `label`), literal `text`, the sections
(`section`, `subsection`, `subsubsection`, `problem`, `exercise`, `example`),
`functionIterates`, `repeat` (over a function's iterates), `clampNumber`,
`polyline`, `triggerSet` and `updateValue`, the text and layout containers
`title`, `ref`, `ul`, `li`, `m`, `md`, `mrow`, `aside`, `sideBySide`,
`stack`, `tabular`, `spreadsheet`, `row`, `cell` and `legend`. With the
`testing` feature (on under `cargo test`), also `op`, which names an
operator directly. A `<math>` tuple of three or more entries is a tuple
(`$t[2]`); a function of several variables or with a tuple value is only
iterated. `fixtures/sir.doenet` is a document using most of these.

## Running locally

- `npm test`: builds `@doenet/parser`, then `cargo test --workspace`
  (needs `node`). The tests in `crates/cells-core/tests/` load DoenetML
  snippets with `testing::test_utils::load` and read cells by component
  name and prop; copy one to try a document without the browser.
- `npm run build`: compiles the core to wasm in `pkg/`, which
  `packages/cells-viewer` serves in the browser. Its `npm run dev` depends
  on this through wireit, so running the viewer rebuilds a stale `pkg/`.
- `npm run lint`: fmt and clippy, warnings denied.
- `cargo test` also runs in CI (`.github/workflows/cells-core.yml`); fmt
  and clippy in the `Lint Rust Code` job of `ci.yml`.
- `npm run fixtures`, `npm run golden-diff -- [rev]`: the generated
  documents and the refactoring guard.
- `npm run parity:cells` in `packages/doenetml-worker-javascript` runs the
  JavaScript core's test suite against this core and writes the gap list to
  `CELLS_CORE_PARITY.md` there.

`Cargo.lock` is committed, unlike the worker's in
`packages/doenetml-worker-rust` (the root `.gitignore` makes an exception
for it): this workspace builds a wasm binary and the benchmark drivers,
and the golden diff and the speed comparisons below only mean something
when every machine builds the same dependency tree, `math-expressions`
being pinned to a git revision.

Speed is measured by `packages/benchmark` (its `scripts/perf-diff.sh`
compares a base commit with the working tree).
