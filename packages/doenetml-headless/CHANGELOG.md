# @doenet/doenetml-headless

## 0.8.0

### Patch Changes

- 5b2c07f: An `<answer>`'s type comes from its input (D55), so `type` is needed only when nothing else decides it.

    - **The input written inside the answer decides its type.** `<answer><textInput/>hello there</answer>` now reads "hello there" as a text, and `<answer><booleanInput/>true</answer>` reads `true` as a boolean, so entering the correct response earns credit. Before, plain text in an award was a math unless `type` was written, whatever the input, and these earned no credit, silently.
    - **With no input inside, the awards' typed content decides it, references included.** `<answer>$t</answer>`, with `t` a `<text>`, adds a `<textInput>` (it added a `<mathInput>`), and in `<answer><award><text>hello</text></award><award credit="0.5">hi</award></answer>` the second award's "hi" is a text too. Plain text is a math only when nothing decides the type.
    - **A `type` in another case or with spaces around it is applied as the type it names:** `type="Text"` and `type="text "` are text answers. (A `type` is a tag name matched exactly, D63 decision 4; the `w0197` for another case comes separately.) Before, it was warned of as an invalid type and the answer read its content as a math. A `type` that names no type is still warned of, and an input written inside still decides.
    - **A `type` that disagrees with the input written inside is an error at load,** a new `doenet-e0092`, at the attribute. The input's type is used. A `type` that agrees is allowed, and `type="videoWatched"` is unchanged.
    - **New warnings at load** for an award's content that can never earn credit:
        - content of another type than the input it is compared with (`<textInput/>` beside `<math>2</math>`), `doenet-w0205`. Only an award's one component is warned of: content of more than one child is wrapped in the answer's type (`<award><text>x</text>y</award>` is a math in a math answer);
        - an award with content and no `<when>` in an answer with more than one input, which is compared with none of them, `doenet-w0206`;
        - an award with content and no `<when>` in an answer whose input is written outside it with `forAnswer`, which is compared with an input the answer adds, `doenet-w0207`.

        An award whose content is one `<when>` (also a `<when>` written directly in the answer, which its sugar wraps in an award, or one inside a composite such as a `<group>`) compares in the `<when>`, so it is not warned of. A reference to a `<when>` (`$w`) is its value, a boolean compared with the input: `<answer>$w</answer>` adds a `<booleanInput>`.

- 4a731cf: Answers, inputs and actions: composites hold awards and matrix rows, one `submitLabel`, an answer's label on its input, and new warnings where something did nothing silently.

    - **An `<award>` inside a composite is the answer's award** (COMP-1, #1874). `<answer><group><award>…</award></group></answer>`, and the same with a `<select>`'s option, a `<repeat>` or a `<conditionalContent>`, used to wrap the composite in a second award, so the authored award never graded (credit 0, with a misleading `doenet-w0107`). Each now grades, one award per award written (two from a `<repeat>` of two), and reads its plain text as the answer's type. A `<setup>` beside an award is no longer wrapped in an award of its own.
    - **A `<matrix>`'s rows and columns can come from a composite** (#1873): rows from a `<repeat>`, a `<group>`, a case or an option are the matrix's rows. Before, the matrix was an empty 1×1 with misleading `doenet-w0107`s. A `<math>` beside such rows is ignored, with `doenet-w0194`, as beside rows written out.
    - **One `submitLabel`** (D66 decision 15, #349). Its default is "Check Work" when correctness is shown and "Submit Response" when it isn't, and an authored `submitLabel` is used in both cases. `submitLabelNoCorrectness` is retired: it is read as `submitLabel`, with a deprecation warning (`doenet-w0108`), or dropped (`doenet-w0109`) where `submitLabel` is also written. `$a.submitLabelNoCorrectness` no longer exists. This applies to `<answer>` and to the section-wide check-work button.
    - **An `<answer>`'s `<label>` labels its one input when the input is written directly in it** and has no label of its own (D66 decision 2, #1674), as it labels an input the answer adds. Before, the label was shown nowhere and the input's accessible name was generic. Where it can't (more than one input, or an input with a label of its own), a new warning, `doenet-w0209`.
    - **`<orbitalDiagramInput>` and `<subsetOfRealsInput>` take a `<label>`** and `labelIsName` (CTX-11, #1279), shown above the widget, which it names. Before, a `<label>` was an invalid child.
    - **A bare `$choice` in a `<choiceInput>`** (`<choiceInput>$c1 $c2</choiceInput>`) is whether the choice was submitted, so it adds no choice (D21, D42). It now gives a new warning, `doenet-w0210`, that says so and suggests `<choice copy="$c1"/>`, in place of a `doenet-w0107` about invalid `<boolean>` children (#2097). A `<choiceInput>` no longer selects an index past its choices.
    - **Two references that name nothing are not each other's responses** (VAL-5, #1853): `<award referencesAreResponses="$nope1"><when>$nope2 = 1</when></award>` records no response, also for indices (`$mis[$nope1]` and `$mis[$nope2]`).
    - **A `<callAction>` whose `target` names a property** (`$p.x`, `$p.styleDescription[1]`) names no component and does nothing. It now gives a new warning at load, `doenet-w0211` (#1565), where the property follows a component that is written out and isn't a composite (after a composite, or a component made by `copy` or `extend`, a name may name what it makes or has from its source).
    - **From #2657**, after the answer's type was decided from its input (D55):
        - an answer's `type` is trimmed, so `type=" videoWatched "` is a video answer (D67 decision 2);
        - content that is both of another type than the input and a boolean–number mix (`<number>$b</number>` in a `<booleanInput>` answer) gets only `doenet-w0205`, whose advice resolves both (D67 decision 3);
        - `doenet-w0205` for a reference names its value: "`$ti` gives a `text`" (D67 decision 4);
        - `doenet-w0078` (a `type` that names no type) is at the `type` attribute in every answer, a choice answer included (D67 decision 5);
        - an `<award copy>` whose source is outside the answer reads its plain text as the answer's type: `<award name="aw">hello</award><answer><textInput/><award copy="$aw"/></answer>` earns credit for "hello" (it earned 0);
        - an `<answer copy>` with awards of its own uses its source's input, and reads its awards' text as that input's type (it added a second input and earned 0);
        - `doenet-w0205` is given for content of another type inside a composite (`<textInput/><group><math>x</math></group>`);
        - `doenet-w0206` and `doenet-w0207` are no longer given for a reference with an index to a composite holding a `<when>` (`<award>$r[1]</award>`), and are given for a copy of a composite that holds no `<when>`, and for a `<when>` inside a `<p>` in a `<group>`;
        - `doenet-w0207` no longer names an input the answer doesn't add, and `doenet-w0205` is not given then; `doenet-e0092` quotes the `type` as written;
        - what is reported of an answer's own content (`doenet-w0203`) is located at the content (from its first to its last component, or text between the components written around it), not at the whole answer, where that can be told.

- edaab33: A `<boolean>` whose content holds a boolean–number mix, or compares something that names nothing, is now a blank, not `false`, so an answer no longer credits the response "false" for it. `<number convertBoolean>` counts every boolean in its content, more mixes are found when the document loads, and a boolean can't be made from a label.

    - **Logic holding a mix is a blank** (`＿`): `<boolean>$b = 1</boolean>`, `<boolean>$n + 0</boolean>`, and logic built on them, such as `not ($b = 1)` or a `<when>` condition. Before, each was `false` (and `not ($b = 1)` `true`), so `<answer><booleanInput/><award>$b = 1</award></answer>` gave full credit for the response "false". A reference to such a `<boolean>` is a blank too.
    - **A comparison with a missing operand is a blank** too: `<boolean>$nothing = 1</boolean>`, `$nothing != 1`, `not ($nothing = 1)` and a comparison of two missing values are `＿`, where before they were `false` (or `true`, for `!=` and `not`). So an answer whose condition compares something that names nothing, or a value that has none yet (a `<choiceInput>`'s `selectedIndex` before a choice), no longer gives credit, for the response "false" either. An input left blank is not missing: `$mi != x` is still true while `mi` is empty, in a `<number convertBoolean>` and a `credit` too.
    - **A missing boolean is `false` wherever it is read as a condition**, through one rule for every tag whose value is a boolean: a `hide`, a `<case>`'s `condition` or an `<award>` reading `$nothing != 1` acts as `false` (before, `hide="$nothing != 1"` hid and the `<case>` was chosen), and so does one that refers to a missing boolean: `hide="not $b"`, `hide="$b != true"` and `condition="not $bl[5]"` (an entry past the end of a list) no longer hide or choose while `b` or the entry is missing. `<isNumber>`, `<isInteger>`, `<isBetween>`, `<matchesPattern>` and `<hasSameFactoring>` with a missing operand are now missing (`＿`) as the other boolean tags are, where before they were `false`, so `not` of one is missing too.
    - **In a `<number convertBoolean>`, and so in `credit`, a boolean compared with a number compares 1 or 0**: `<number convertBoolean>$b = 1</number>` and `credit="$b = 1"` are 1 when `b` is true (before, a blank), and `$n = true` compares `n` with 1. Each now gets a warning, `doenet-w0208`, suggesting a plainer form that means the same (`$b` for `$b = 1`, `not $b` for `$b = 0`, `$n != 1` for `$n != true`). Logic compared with a number there (`($n > 1) = 1`) gets it too.
    - **`<number convertBoolean>` counts every boolean in its content** as 1 or 0: `<number convertBoolean>$b + 1</number>` is `2` when `b` is true (before, `NaN`), and `<number convertBoolean>($n > 1) + $b</number>` adds a comparison and a boolean. Content that is all literal counts its booleans too: `<number convertBoolean>(1 < 2) + 1</number>` is `2` (before, `0`). Anything else is read as a `<number>` reads it: `<number convertBoolean>2x</number>` is `NaN` (before, `0`). A missing operand makes it a blank: `<number convertBoolean>$nothing</number>` was `1`. An `<award>`'s or a `<choice>`'s `credit` is such a number, so `credit="$nothing"` (a reference to nothing) now gives no credit; before, it gave full credit.
    - **More mixes are warned of at load** (`doenet-w0203`), each a blank: a number compared with `true` or `false` (`<boolean>$n = true</boolean>`, with its own message), a boolean in arithmetic inside a comparison (`<boolean>$b + 1 = 2</boolean>`), a mix inside logic that is compared (`$bi = not ($b = 1)`), and a boolean beside other values in a `<group>` inside a `<math>` (before, the boolean was dropped with `doenet-w0107`).
    - **A tag written where a mix is keeps its own value**: in `<math><boolean name="q">true</boolean> + 1</math>`, the math is `＿ + 1` as before, but `$q` elsewhere is now `true` rather than a blank.
    - **`<boolean extend="$l"/>` of a `<label>` is an error** (`doenet-e0065`), as for any other pair of unrelated types: a boolean is made only from a text, and a label is not one. Before, it was `false` with no message. A label can still be made a `<text>`.

- 1359053: A boolean is never read as a number, nor a number as a boolean, unless the author asks: `<number convertBoolean>` is the one place a boolean counts as 1 or 0, and a comparison such as `$n != 0` is how a number decides a boolean. Each other mix is a blank in its place, with a warning when the document loads, wherever it is written (on an `extend` or a `copy` too: `<p extend="$p" hide="$n"/>`, `<boolean extend="$c">$n</boolean>`), and a type change between them is an error. Ordering a text against a number is warned of too.

    - **A boolean where a number or a math is wanted** is a blank, with the warning `doenet-w0203`, which suggests `<number convertBoolean>$b</number>` (written outside the attribute and named, for a boolean in one): a boolean in a `<math>` (`<math>$b + 1</math>` is `＿ + 1`), in a `<number>` or `<integer>` without `convertBoolean` (`<number>$b</number>` is a blank), in a `<mathList>` or `<numberList>`, in `<sum>` and the other math operators, `<isNumber>`, `<count>`, a `<function>`, an `<interval>`, a `<matrix>` row, a `<point>` or `<vector>`, and in a math attribute (`<point x="$b">`, `<sequence from="$b">`). Before, a boolean in a `<math>` or an operator was dropped with `doenet-w0107` ("Invalid children"), and `<number>$b</number>` was `NaN`. A list of booleans, an entry of one, and a repeat's value that is a boolean are read the same way. Where a text is wanted (`<text>$b</text>`, a `<p>`), a boolean is still the word `true` or `false`.
    - **A number or a math where a boolean is wanted** is a blank, with `doenet-w0203`, which suggests a comparison: `<boolean>$n</boolean>`, `<boolean>2</boolean>`, an operand of `and`, `or` or `not` (`<boolean>$b and $n</boolean>`), a boolean attribute (`hide="$n"`, `hide="1"`, a `<case>`'s `condition`), a number in a `<booleanList>`, and a number in `<and>` or `<or>`. Before, a nonzero number was silently `true`, and a number in a `<booleanList>`, `<and>` or `<or>` was dropped with `doenet-w0107`. Write `true` or `false` for a literal, and a comparison (`$n > 0`, `$n != 0`) to test a number.
    - **A boolean compared with a number** (`<boolean>$b = 1</boolean>`) is a blank, with `doenet-w0203`. `$b = true` compares booleans, as before.
    - **`<mathInput bindValueTo="$b">`** of a boolean, and **`<booleanInput bindValueTo="$n">`** of a number, are bound to a blank, with `doenet-w0203`, which suggests the input of the other type. Before, a `<booleanInput>` bound to a number showed a nonzero number as checked, and unchecking it changed nothing.
    - **A type change between them is an error** (`doenet-e0065`): `<math extend="$b"/>`, `<number copy="$b"/>` and `<math extend="$bi"/>` of a `<booleanInput>`, with the same suggestion of `<number convertBoolean>`, and `<boolean extend="$n"/>` of a number or a math, which suggests a comparison. Before, they were allowed. A boolean and a text still convert both ways.
    - **A boolean in a random choice's parameter** (`<selectFromSequence to="$b+2">`) can't be analysed, `doenet-e0074`, as any parameter that isn't a number is. Through a `<number convertBoolean>` it is read as before.
    - **`credit` on an `<award>` or `<choice>` still takes a boolean**: `credit="$b"`, `credit="$n > 2"`, `credit="$b and not $c"` and `credit="true"` give full credit when true and none when false, with no warning, since `credit` is read as a `<number convertBoolean>`.
    - **Ordering a text against a number** with `<`, `>`, `<=` or `>=` (`$t > 2`) is never true, and now warns when the document loads (`doenet-w0204`). Nothing is converted, and `=` is unchanged. For a section's `sectionNumber`, a text such as `2.1`, the warning suggests the section's `ownNumber`, its position as a number.
    - The editor's schema check flags a `<boolean>` or `<booleanList>` written inside a `<math>` or another container that takes maths, as it did before.

- ad1a769: Fixes for documents that hung, stopped, or showed a stale blank:

    - **A cycle through a `<caption>` no longer hangs the document.** `<figure><caption name="ca"><span>$b</span></caption><graph><point name="a"><label>$ca</label></point><point name="b" extend="$a"/></graph></figure>` never finished loading: `b` copies `a`'s label, which shows the caption, which shows `b`. It is now `doenet-e0005` at `$b` and at `$ca` when the document loads, and the rest renders. The same holds for the other tags whose content is what is written in them, which hung the same way: `<figure>`, `<table>`, `<tabular>`, `<row>`, `<column>`, `<cell>`, `<cellBlock>`, `<spreadsheet>`, `<chart>`, `<sideBySide>`, `<sbsGroup>`, `<stack>`, `<page>`, `<cascade>`, `<hint>`, `<feedback>`, `<solution>`, `<givenAnswer>`, `<description>`, `<asList>` and `<ref>`. A reference to one of them written inside it (`<hint name="h"><p>$h</p></hint>`) is `doenet-e0005` when the document loads, as before, though in a `<solution>` or a `<givenAnswer>` it was not reported. A `<graph>` is now one of these tags too: `<graph name="g"><text>$g</text></graph>` was already `doenet-e0005` at `$g`, and its message now names the `<graph>`.
    - **A point written with `extend` in a paragraph whose label shows what reads its value now loads.** With `<answer><award name="q"><when>$b=1</when></award></answer>` and `<point name="a"><label>$q</label></point>`, a `<p><point name="b" extend="$a"/></p>` was `doenet-e0005`, though `$b` in the `<when>` reads `b`'s value, not its label. It loads, as it did in a `<graph>`, and so does the same point in any of the tags above. Where `a`'s label shows the tag holding `b` (`<p name="q"><point name="b" extend="$a"/></p>` with `<label>$q</label>`), `b` holds itself: that is `doenet-e0005` at `b` and at `$q` when the document loads, in a `<p>` as before and now in the tags above too, with `extend`, `copy` or `copyWithState`. With `copy` in a `<cell>` or a `<hint>`, the document hung.
    - **A group and a component in it that are each fixed by their own `fixed`** (`<group name="g" fixed="$g.fixed"><number name="n" fixed="$n.fixed">`) are each `doenet-e0005`. Before, only the group's was reported, and the number was gone from the document. A component fixed by whether something it holds is fixed (`<p fixed="$n.fixed">` around `n`) is `doenet-e0005` too, and so is the same construction with `fixLocation`. Reading a component's value, or the `fixed` of what holds it, is not a cycle.
    - **A point made with `copy` (or `copyWithState`) of a point whose label shows the copy now loads.** In `<point name="a"><label>$b</label></point><point name="b" copy="$a"/>`, both labels show `b`'s coordinates, as they do with `extend`. It was `doenet-e0005`.
    - **An index into an extend of a repeat's iteration follows a change of case.** With `<math name="e2" extend="$r[1]"/>`, where the iteration shows `$cc.x` of a `<conditionalContent>`, `$e2[2]` was `＿` after the case changed back, though `$e2` was right.
    - **A select option written as `<group extend="$g"/>`, `<group copy="$g"/>` or a bare `$g` is read through the group it names.** When `g` holds several components and another option holds one, an index after the select (`$s[1][2]`) is `doenet-w0191` when the document loads, in every variant, as for a `<group>` written in the option. Before, only the variants picking that option were warned, once the document ran. A select with one option, `<option>$g</option>`, whose group holds several, gets `doenet-w0191` at load in place of `doenet-w0188` when the document ran. A group extended there holding one component passes the index to it, as before.

- 08c128b: Names are matched exactly in a few more places (D51, D62), and some cases that were silent or had an uncoded error now have a diagnostic:

    - **An attribute written twice in the same case** (`<math simplify="full" simplify="none">`) uses the first and ignores the others, each with the new warning `doenet-w0201` at the repeated attribute. Before, the last one was used, silently.
    - **A value that names a tag or a property is a name**, matched exactly. `<collect componentType="Point">` and `<sort sortByProp="X">` (of points) are applied as `point` and `x` for now, with `doenet-w0197`, the warning an attribute in another case gets, saying it will be an error in a later release. Before, `componentType` was matched without case, silently, and `sortByProp="X"` left the items unsorted, silently. A `componentType` that comes from a reference (`componentType="$t"`, with `t` the text `Point`) is matched exactly too, with no fallback: it collects nothing, with `doenet-w0073` suggesting the spelling, where before it collected the points, silently. Keywords in values (`simplify="FULL"`, `hide="True"`) stay case-insensitive.
    - **An attribute a `<collect>` passes on, in another case** (`<collect componentType="math" DisplayDigits="2">`, `Hide`) is applied for now, as the spelling of the tag `componentType` names, with `doenet-w0197`, as on any other tag. Before, it was ignored, silently.
    - **`sortByProp` on bare text** (`<sort sortByProp="x">3 1 2</sort>`) that names no property of the pieces is `doenet-w0198` at load, as it is for items written as tags.
    - **An attribute read as text, written with a reference** (`<sort sortByProp="$t">`, `<sort type="$t">`) is the new error `doenet-e0090` at the attribute, saying to write its value as text, also on a tag written with `extend` or `copy` of a component (`<sort extend="$s" sortByProp="$t"/>`). Before, it was an uncoded error at the component, and with `extend` or `copy` the whole document failed to load.
    - **The editor** matches tag names exactly, as the document does: `<MATH>` gets "Element `<MATH>` is not a recognized Doenet element. Did you mean `<math>`?" (`doenet-w0112`), where before it was checked as `<math>`, with no warning. An attribute in another case (`<graph XMIN="-5"/>`), or a module's declared attribute in another case, gets `doenet-w0197` in the editor, as in the document, where before it was accepted silently.

- b8fb65e: A tag made with `extend`, `copy` or `copyWithState` from something it can't be is now an error when the document loads, where several such tags loaded silently:

    - **A `<group>` made from a collection, or from one component that isn't a composite, is an error** (`doenet-e0065`). A collection is a `<repeat>`, `<repeatForSequence>`, a list (`<mathList>`, `<pointList>`, …), `<sequence>`, `<collect>`, `<sort>`, `<shuffle>`, or a `<select>` or other chooser that picks several: before, a group made from a repeat or a select of several showed nothing, with no message, and one made from a list, a `<sequence>`, a `<collect>`, a `<sort>` or a `<shuffle>` showed its items as the group's. One component that isn't a composite is a value, an input or an object (`<math>`, `<number>`, `<text>`, `<mathInput>`, `<answer>`, `<point>`, …) or a container (`<p>`, `<section>`, `<graph>`, `<problem>`, …): before, `<group extend="$m"/>` of a `<math>` showed the math, and one made from a `<choiceInput>` or an `<answer>` showed nothing, with an internal message about a state variable. The message names the forms that work: `<group>$r</group>` or `<group>$m</group>`, a group holding it, and `<repeat extend="$r"/>` or `<math extend="$m"/>`, the same component again, written with the attribute the author used. This holds also for a component named inside a section, a group, a case, an option or an iteration (`$sec.m`, `$outer[1].r`), for the value of a `<repeat>` whose `for` gives it one type (`$v`, `$r[1].v`), and for a property or an entry of a list, as what it gives: `<group extend="$m.value"/>`, `$P.x` and `$ml[1]` as one component (they showed the value), `$P.xs` and `$poly.vertices` as a list (they showed nothing). A `<group>` made from a group (or a `<module>`), an iteration (`$r[1]`), a pick, a `<conditionalContent>` or a one-pick `<select>` is unchanged, as is one made from another composite or from a property whose type the DoenetML does not decide.
    - **A `<repeat>`, `<select>`, `<collect>`, `<sort>` or other tag that makes its content itself, made from anything but the same tag, is `doenet-e0071`** however the source is written: `<repeat extend="$n"/>` of a `<number>` and `<repeat extend="$r[1]"/>` of an iteration were `doenet-e0065`, which named the source's type as though another type might work. It is now reported when the document loads also in a case that isn't true yet.
    - **`<sampleRandomNumbers extend="$s"/>` of a `<selectRandomNumbers>` is `doenet-e0071`**, as the reverse already was, in place of a misleading "invalid children" warning. So is `<sequence extend="$s"/>` of a `<selectFromSequence>`.
    - **An index into a `<conditionalContent>` is type-checked when the document loads**: `<point extend="$cc[1]"/>` of cases holding a text, and `<boolean extend="$cc[1]"/>` of cases holding a math, are `doenet-e0065`, as without the index. Before, they were `(0, 0)` with an "invalid children" warning, and a boolean with no message.
    - **A scalar tag made from an iteration, a group, a case or an option holding a list whose entries are written out (`1 2 3`) is decided by those entries**, as `<math extend="$ml"/>` already was: more than one, counting what is beside the list, is `doenet-e0064`. `<math extend="$r[1]"/>` of `<repeat name="r" for="1">$ml</repeat>` showed a blank with no message, and `<text extend="$r[1]"/>` of one holding `<mathList>1 2</mathList>` the entries run together (`1, 2`). The message gives an index that names one entry, such as `$r[1][1]`. A list of one entry is that entry, so a `<number>` made from an iteration holding `<booleanList>true</booleanList>` is `doenet-e0065`, as from a `<boolean>`; it was `NaN`.

- 2a96231: A document or aggregating section with nothing scored (no answers, or every answer `weight="0"`) now has a `creditAchievedIfSubmit` of 1 rather than `NaN`, matching `creditAchieved`. The `NaN` no longer spreads to the containers around it, and a section-wide check work over only weight-0 answers records a credit of 1 in its `submitted` event. `gradeState` in `@doenet/doenetml-headless` reports these documents with a credit rather than `NaN`.
- 35120de: Fewer false circular-dependency errors around a section's number, and more documents with cycles load (D61, DIAG-5).

    - **A section's number and a `condition`.** A reference to a section's number (`$s.sectionNumber`, `$s.ownNumber`, `$s.title`) inside a composite before the section is a circular-dependency error (`doenet-e0005`) found when the document loads only when it can change how many sections the composite makes, such as a `<repeatForSequence>`'s `from`, `to` or `length`, a `<repeat>`'s `for`, a `<select>`'s `numToSelect`. One in a `condition` of a `<conditionalContent>` or a `<case>`, or a `selectWeight`, can only switch which case is shown, so it is no longer reported when the document loads.
